# /paper-code — 계측기 감사

**파서도 계측기의 일부다.** 연구 코드의 결함은 크래시하지 않는다.
그럴듯한 숫자를 내고, 그 숫자가 표에 들어가고, 그 표가 논문의 주장이 된다.

일반 코드리뷰와 다르다. 여기서 묻는 것은 "이 코드가 도는가"가 아니라
**"이 코드가 잰다고 말하는 것을 실제로 재는가"** 이다.

## 표적으로 삼는 결함

전부 실제로 겪은 것이다. 각각 조용히 통과했고, 세어봐야 드러났다.

| 결함 | 어떻게 보였나 | 실제 원인 |
|---|---|---|
| **하네스 실패를 답변으로 기록** | 383셀이 `no_json_prose`(모델이 답을 거부한 것처럼) | OAuth 만료. 셀은 재시도 대상에서도 빠짐 |
| **전송 오류를 영구 실패로** | 56셀 "prepayment credits are depleted" | 429였고 몇 분 뒤 같은 키가 정상 응답 |
| **경로마다 다른 성공 판정** | Gemini 447개 전부 실패로 집계 | REST는 `returncode`를 설정하지 않음 |
| **집계값을 속성으로 오독** | fable 249개 중 31개 성공 → 무능한 모델 | 하루치 장애. 날짜별로 쪼개면 15/15와 0/185 |
| **파서가 유효 응답을 폐기** | 13셀이 조용히 사라짐 | 이중 인코딩 JSON, 낡은 키 요구 조건 |
| **식별자 미전달** | 쌍 105개 (실제 214개) | draw 인덱스가 스코어 행에 안 실려 검정력 절반 |
| **축 혼동** | 모든 패턴이 같은 모양으로 그려짐 | 참조계는 z-up, 카메라 외부파라미터는 y-up |
| **게이트 이름 불일치** | 단계 전체가 건너뛰어지고 성공 보고 | `..._v2.ready`를 기다렸으나 파일명은 `..._v1` |

공통점: **실패가 데이터처럼 생겼다는 것.**

## 절차

1. **경계를 찾는다** — 데이터가 형태를 바꾸는 지점을 나열한다.
   전송 → 원문 → 파싱 → 점수 → 집계 → 표/그림.
   결함은 거의 항상 경계에 있다. 각 단계 안이 아니라.

2. **각 경계에서 묻는다:**

   **전송 → 원문**
   - 실패가 어떻게 기록되나. 하네스 실패와 모델 응답이 **구분되나**
   - 재시도가 있나. 일시적 오류(429/5xx)와 영구 오류가 구분되나
   - 오류 본문을 믿고 있나 (429가 "크레딧 소진"이라고 말할 수 있다)
   - 전송 경로가 둘 이상이면 **성공 판정이 경로마다 같은가**

   **원문 → 파싱**
   - 거절 사유가 기록되나. `None`으로 뭉뚱그리지 않나
   - **거절된 것 중 유효한 답이 있나** — 이건 반드시 세어본다
   - 파서를 고쳤을 때 몇 개가 어느 방향으로 움직이는지 세나
   - 관대해지는 변경이 오류 응답을 답변으로 승격시키지 않나

   **파싱 → 점수**
   - 셀을 식별하는 키가 **전부** 실려 있나 (조건, 반복, 장면, 모델)
   - 결측이 0으로 취급되지 않나

   **점수 → 집계**
   - 표본의 **층위**가 맞나. 셀 1000개라도 방이 4개면 방이 표본이다
   - 여러 조건에 걸친 집계값을 단일 속성으로 읽고 있지 않나
   - 날짜·배치별로 쪼개면 다른 그림이 나오나

   **집계 → 그림**
   - 축이 맞나. 좌표계 규약(z-up/y-up)이 섞이지 않았나
   - 그림이 본문의 주장과 같은 부분집합에서 나왔나

3. **세어서 확인한다** — 논증하지 말고 센다.
   "이 변경은 안전하다"가 아니라 "이 변경으로 7개가 회수되고 0개가 회귀한다"로 말한다.
   변경 전후를 비교하는 일회용 스크립트를 쓰는 것이 정당한 비용이다.

4. **조용한 누락을 찾는다** — 상한, 샘플링, 재시도 없음, `except: pass`, 기본값 대입.
   전부 로그를 남기는지 본다. 말없이 잘린 결과는 "전부 처리함"으로 읽힌다.

5. **보고** — 각 결함에 대해: 어디서, 어떻게 보였는지, 실제 원인, 몇 개가 영향받는지.
   **영향 개수를 반드시 센다.** 개수 없는 지적은 우선순위를 못 정한다.

## 규칙

- **고치기 전에 센다.** 몇 개가 어느 방향으로 움직이는지 모르면 그 수정이 개선인지 알 수 없다.
- **회귀는 회수와 다르게 취급한다.** 기록된 답을 잃는 변경은 버려진 답을 줍는 변경과 별개의 결정이다. 회귀가 있으면 멈추고 보고한다.
- **실패는 기록하지 말고 던진다** — 하네스 실패에 한해. 기록 안 된 셀은 재시도되지만, 잘못 기록된 셀은 재시도 목록에서 빠진다.
- **첫 실패에서 멈춘다.** 자격증명이 죽은 뒤 계속 도는 스윕은 5분짜리 중단을 하룻밤치 쓰레기로 바꾼다.
- **논문에 쓴다.** 발견한 계측기 결함은 한계 절이 아니라 방법의 일부다. 무엇을 잘못 쟀고 어떻게 고쳤는지 적는 것이 재현성이다.
- 코드가 git 아래 없으면 **먼저 그것부터 지적한다.** 되돌릴 지점 없이 계측기를 고치는 것은 그 자체가 위험이다.
