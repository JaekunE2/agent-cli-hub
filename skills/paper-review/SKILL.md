# /paper-review — 리뷰어처럼 읽기

저자가 아니라 **거절 사유를 찾는 사람**으로 읽는다.
목표는 원고를 칭찬하는 것이 아니라, 리뷰어가 칠 곳을 저자가 먼저 찾는 것이다.

## 읽는 순서

리뷰어는 처음부터 순서대로 읽지 않는다. 이 순서로 읽고, 이 순서로 지적한다.

1. **초록 → 그림 → 표 → 결론.** 대부분의 리뷰어가 실제로 보는 것의 대부분이다.
   여기서 말이 안 되면 나머지는 읽히지 않는다.
2. **초록의 주장이 표에 있는가.** 없으면 그 자체가 최상위 지적이다.
3. **그림 하나만 보고 논지를 알 수 있는가.**
4. 그 다음에 본문.

## 지적의 우선순위

거절로 이어지는 순서다. 사소한 것부터 나열하면 심각한 것이 묻힌다.

| 등급 | 유형 | 예 |
|---|---|---|
| **치명** | 주장이 근거보다 넓다 | 관찰 연구인데 인과로 서술 |
| **치명** | 대조군·기저선 부재 | 무엇과 비교한 것인지 불명 |
| **치명** | 측정 도구 자체의 결함 | 파서가 유효 응답을 버리고 있었음 |
| **중대** | 통계 부재·부적절 | 다중비교 보정 없음, 표본 층위 혼동 |
| **중대** | 재현 불가 | 상수·시드·버전 미기재 |
| **중대** | 그림이 주장을 뒷받침 안 함 | 축이 틀렸거나 논지와 무관 |
| **경미** | 표기·용어 불일치 | 같은 양을 두 이름으로 부름 |
| **경미** | 분량·형식 | 페이지 초과, 캡션 위치 |

## 절차

1. **투고처 규정 확인** — 인자로 학회·저널이 오면 그 규정(페이지, 부록 허용, 익명화, 형식)을 먼저 본다.
   페이지 초과는 리뷰 전에 데스크 리젝이 되므로 **가장 먼저 확인한다.**

2. **주장 목록화** — 초록·기여 목록·결론에서 뽑는다. `/paper-claims`가 이미 있으면 그것을 쓴다.

3. **각 주장을 공격한다** — 다음을 순서대로 묻는다:
   - 이 결과를 만드는 **다른 설명**이 있나 (교란 변수, 선택 편향, 측정 방식)
   - 표본이 몇인가. **어느 층위에서** 몇인가 (셀 1000개라도 방이 4개면 방이 표본이다)
   - 유의성이 있나. 다중비교 보정 후에도 남나
   - **측정 도구를 검증했나.** 파서·스코어러·로더 자체가 틀렸을 가능성을 저자가 다뤘나
   - 재현 가능한가. 다른 사람이 같은 수를 얻을 수 있나

4. **각 지적을 셋으로 분류한다:**

   | 분류 | 뜻 |
   |---|---|
   | **지금 고칠 것** | 글로 해결됨. 주장 축소, 조건 명시, 용어 통일 |
   | **한계로 인정할 것** | 범위의 문제. 사과가 아니라 범위로 적으면 방어된다 |
   | **실험이 필요한 것** | 데이터로만 해결됨. 남은 기간에 가능한지 함께 판단 |

   **세 번째는 개수와 비용을 함께 적는다.** "방 4개 더"가 검정력 35%→77%인지 알아야 결정할 수 있다.

5. **강한 부분도 적는다** — 리버털에서 어디를 지킬지 정하려면 무엇이 튼튼한지 알아야 한다.

6. **보고** — 등급순으로. 각 항목에 위치(절·줄), 문제, 조치안.

## 규칙

- **저자의 의도를 변호하지 않는다.** "이렇게 읽으면 맞다"는 리뷰어에게 통하지 않는다. 그렇게 읽히면 그게 문제다.
- **고칠 수 없는 것도 지적한다.** 실험이 불가능해도 리뷰어는 지적한다. 미리 알고 한계 절에 쓰는 것과 리뷰에서 처음 듣는 것은 다르다.
- **측정 도구를 의심한다.** 연구 코드의 결함은 조용하다 — 죽지 않고 그럴듯한 수를 낸다. 저자가 이걸 다뤘는지 반드시 본다. (`/paper-code` 참조)
- **분량 초과는 내용 문제로 취급한다.** 부록을 보충자료로 옮길지는 저자 결정이지만, 결정 안 된 채로 두면 데스크 리젝이다.
- 지적마다 **수정 문안**을 제시한다. 지적만 하면 저자가 원문을 남긴다.

## 관련

- 수치 검증: `/paper-numbers`
- 측정 코드 감사: `/paper-code`
