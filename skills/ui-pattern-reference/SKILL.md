# UI Pattern Reference

1. Identify the user's primary task, target platform, smallest supported viewport, and costly mistakes. Inspect the existing UI and design system for the same workflow before proposing changes.
2. Read [the source index](references/source-index.md). Select one or two patterns that solve the interaction problem. Prefer current platform guidance for native conventions and web accessibility. Use archival guides to understand the reasoning and discover alternatives.
3. Explain how the pattern changes the screen or behavior. Keep useful conventions from the product and adapt historical examples to its components, visual identity, input methods, and viewport sizes.
4. For a design task, specify hierarchy, interaction, and relevant loading, empty, error, and success states. For a review, describe the observed problem, its impact on the task, and a concrete fix. For implementation, verify the changed path on the relevant viewport and input method.

Give each cited recommendation an identifiable source. Distinguish a documented requirement from your design judgment. Match the output to the requested scope, including analysis-only requests.
